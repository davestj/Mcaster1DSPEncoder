SAST Security Scan Report

Mcaster1DSPEncoder v1.8.0-beta.1 | Scan Date: 2026-03-27 | Scanner: Claude Opus 4.6 Manual Review

Executive Summary

A comprehensive static analysis was performed on all C++ source files (src/linux/*.cpp, src/linux/*.h), PHP API files (src/linux/web_ui/app/api/*.php), PHP include files (src/linux/web_ui/app/inc/*.php), and PHP page files (src/linux/web_ui/*.php). The analysis covered SQL injection, command injection, XSS, path traversal, authentication weaknesses, information disclosure, insecure defaults, and denial of service vectors.

Total files scanned: 82 (41 C++, 41 PHP). The codebase demonstrates generally strong security practices including parameterized PDO queries in PHP, mysql_real_escape_string in C++, escapeshellarg() on all shell commands, and h() HTML escaping. Several defense-in-depth improvements were identified and patched.

Findings

#SeverityCategoryFileLineDescriptionRemediation
1 CRITICAL Path Traversal http_api.cpp 346-348 Static asset route /(.+\.(css|js|...)) directly concatenates req.matches[1] with g_webroot without checking for .. sequences. A request like GET /../../etc/shadow.css could read arbitrary files if the regex matched. Added .. check before serve_file(). Request returns 400 if path contains ..
2 HIGH Path Traversal http_api.cpp 3176-3186 The handle_php FastCGI bridge constructs script_filename = g_webroot + req.path without sanitizing path traversal sequences. An attacker could potentially request /app/api/../../etc/passwd.php to execute PHP files outside the webroot. Added .. check at the start of handle_php. Returns 400 if path contains ..
3 HIGH Auth: No Rate Limiting http_api.cpp 390-420 The POST /api/v1/auth/login endpoint had no rate limiting. An attacker could brute-force credentials with unlimited attempts per second. With test credentials like hackme, this is especially dangerous if the service is exposed to the internet. Added per-IP rate limiter: 5 attempts per 60-second window. Returns HTTP 429 when exceeded. Counter resets on successful login.
4 HIGH Directory Traversal app/api/tracks.php 1797 The browse_folders action allowed browsing /etc, /root, /var/log, and other sensitive directories. The blocklist only included /proc, /sys, /dev, /run/systemd, /snap. An authenticated attacker could enumerate directory structures in sensitive areas like /etc/ssl/private. Extended blocklist to include /etc, /root, /var/log, /var/run, /tmp, /boot, and changed /run/systemd to /run.
5 MEDIUM Cookie Security http_api.cpp 407-409 The mc1session cookie was missing the Secure flag. On HTTPS connections, this is a best practice to prevent cookie leakage over downgraded HTTP connections. The cookie had HttpOnly and SameSite=Strict but not Secure. Added Secure flag to the Set-Cookie header.
6 MEDIUM SQL Injection (Defense-in-depth) system_health.cpp 194-199 The sl.state string was used directly via %s format specifier in execf() without escaping. While sl.state is derived from an internal C++ enum and is not user-controlled, defense-in-depth demands all string values in SQL be escaped. The track_title was correctly escaped but state was not. Added Mc1Db::escape(sl.state) before using in the execf() call.
7 MEDIUM Information Disclosure app/api/encoders.php Multiple 14 instances of $e->getMessage() exposed raw exception messages (including SQL errors, table names, file paths) in JSON API responses. This gives attackers information about the database schema and internal structure. Added mc1_safe_error() helper to logger.php that logs the real error but returns a generic message to the user (unless debug mode is active).
8 MEDIUM Information Disclosure app/api/servers.php 88,132,182 Same pattern: raw $e->getMessage() in API responses exposes internal error details including SQL errors. Same fix: use mc1_safe_error() helper.
9 MEDIUM Input Reflection (XSS via API) app/api/health.php 146 The unknown action error message reflected the raw $action value: 'Unknown action: ' . $action. While this is a JSON response (not HTML), user input should never be reflected without sanitization as defense-in-depth. Changed to generic message: 'Unknown action' without reflecting user input.
10 LOW Hardcoded Credentials config/mcaster1_rock_yolo.yaml - Test station credentials (djpulse/hackme) are hardcoded in the YAML config and documented in CLAUDE.md. While this is labeled as a test station, if the config is used in production without changing credentials, it creates an obvious entry point. Accepted Risk: documented as test-only. Production deployments must change credentials.
11 LOW Session Token Entropy http_api.cpp 93-101 Session tokens are generated using std::random_device + std::mt19937_64. While random_device sources entropy from the OS, the mt19937_64 PRNG is not cryptographically secure. The VoicTune daemon correctly uses RAND_bytes() from OpenSSL instead. The 256-bit token space makes practical attacks infeasible, but using a CSPRNG is best practice. Accepted Risk for now: 256-bit token space is sufficient. Future improvement: migrate to RAND_bytes().
12 LOW Missing CSRF Protection http_api.cpp - State-changing API endpoints (start/stop encoder, update DSP, delete tracks) do not require CSRF tokens. The SameSite=Strict cookie flag provides some protection, but does not protect against same-site attacks. All endpoints require the mc1session cookie, which mitigates cross-origin attacks. Low risk due to SameSite=Strict + all state changes are POST/PUT with JSON body (browsers do not send JSON bodies in CSRF).
13 LOW Denial of Service http_api.cpp 234-247 serve_file() reads the entire file into memory with std::istreambuf_iterator. A very large file in the webroot would consume proportional memory. However, the webroot only contains PHP/HTML/CSS/JS files (all small), so practical exploitation is limited. Accepted Risk: webroot contains only small web assets.
14 INFO SQL Best Practice vt_db.cpp All VoicTune database module uses escape() on all string values in SQL construction. All integer parameters use std::to_string(). No SQL injection vectors found. No action needed.
15 INFO Command Injection app/api/tracks.php 556,892 All shell_exec() calls use escapeshellarg() on all variable arguments. The ffmpeg commands construct arguments safely. health.php only runs hardcoded system commands (df, pgrep, free, lame --version) with no user input. No action needed. Verified safe usage.
16 INFO XSS Prevention web_ui/*.php All PHP pages consistently use h() (htmlspecialchars) for HTML output and JavaScript uses an esc() function for DOM insertion. The innerHTML usages in encoders.php pass data through esc() before insertion. Previous category system XSS bug was fixed in L5.5 and is documented. No action needed. Verified consistent usage of output escaping.
