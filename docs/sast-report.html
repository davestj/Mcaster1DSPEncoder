Executive Summary

Risk Score: 6.2 / 10 (Medium)

A comprehensive static analysis was performed on the entire codebase: 47 C++ source files (including voictune/, producer/, dsp/), 57 PHP files (web_ui/, app/api/, app/inc/, lang/), and 21 JavaScript files (web_ui/js/). Total: 125 source files scanned across all languages.

The scan covered: SQL injection, command injection, XSS, path traversal, authentication bypass, CSRF, information disclosure, buffer overflow, race conditions, SSRF, insecure file upload, prototype pollution, eval injection, and sensitive data exposure.

The codebase demonstrates strong security practices in most areas: prepared statements in PHP, db.escape() in C++ SQL, escapeshellarg() on all PHP shell commands, h() HTML escaping, realpath()-based upload validation, extension whitelists for uploads, and consistent auth gates. One critical command injection was found and fixed.

1 CRITICAL Command Injection voictune/vt_http_api.cpp 1989-1990 POST /api/v1/ai/podcast/transcribe — The file_path parameter from user JSON input was concatenated directly into a popen() shell command without escaping: "whisper ... " + file_path + " 2>&1". An attacker could inject arbitrary shell commands via a crafted path like "; rm -rf / #". This endpoint requires authentication but is still critical severity. FIXED
2 HIGH Path Traversal voictune/vt_http_api.cpp 1941-1962 POST /api/v1/ai/podcast/transcribe — The same file_path parameter was used with fopen() to check existence, allowing an attacker to probe for arbitrary files on the filesystem (e.g., /etc/shadow). The error message also leaked the full path in the response: "Audio file not found: " + file_path. FIXED
3 HIGH Path Traversal app/api/forensic.php 108-120, 445-460 analyzeFile() and detectEvents() accept a file_path parameter from user input without path traversal validation. While escapeshellarg() prevents command injection in the ffprobe/ffmpeg calls, an authenticated user could analyze metadata of any readable file on the system (e.g., /etc/passwd, config files with secrets). FIXED
4 MEDIUM SSRF app/api/webhooks.php 270 Webhook test/send — The URL for webhook delivery comes from admin-configured data. An admin could set a webhook URL pointing to internal services (e.g., http://127.0.0.1:8330/api/v1/..., http://169.254.169.254/). The file_get_contents() call follows redirects and could reach internal metadata endpoints. Accepted Risk
5 MEDIUM No CSRF Protection All POST APIs - State-changing POST endpoints (encoder start/stop, track delete, user management, webhook config, RTMP start, etc.) do not validate CSRF tokens. The SameSite=Lax cookie flag and JSON Content-Type requirement provide partial protection, but same-site attacks remain possible. Accepted Risk
6 MEDIUM Information Disclosure Multiple PHP APIs Various 20+ instances of $e->getMessage() returned directly in JSON API responses across: servers.php, encoders.php, edit.encoders.class.php, playlist.manager.pro.class.php, profile.usr.class.php, user_auth.php, podcast.php, daw.php. These expose internal SQL errors, table names, column names, and file paths to authenticated users. Low Priority
7 MEDIUM SQL Truncation http_api.cpp 3706, 4071 Fixed-size char sql[2048] buffers used with snprintf() for INSERT statements containing user-supplied escaped strings (episode titles, file paths, tags JSON). If the combined escaped data exceeds 2048 bytes, the SQL is silently truncated, which could cause query errors or — in extreme edge cases — truncation at a point that breaks the escaping. Low Priority
8 MEDIUM Insufficient Path Validation app/api/podcast.php 108, 294, 783, 1000 Multiple podcast actions accept file_path from user input (via DB lookup, so not directly from request in most cases). While escapeshellarg() is used for all shell commands, no explicit path traversal check is performed on paths that come from the request body (e.g., create_episode accepts file_path directly). Low Priority
9 MEDIUM Session Token PRNG http_api.cpp ~95 The main encoder admin session tokens use std::mt19937_64 seeded by std::random_device. While the 256-bit token space prevents practical brute-force, mt19937 is not a CSPRNG. The VoicTune and Producer daemons correctly use RAND_bytes() from OpenSSL. The main admin binary should match. Accepted Risk
10 LOW Hardcoded Credentials config/mcaster1_rock_yolo.yaml - Test credentials djpulse/hackme are in the YAML config and documented in multiple CLAUDE.md files. The config is labeled as a test station, but if deployed to production without changes, provides trivial access. Accepted Risk
11 LOW Missing Rate Limit voictune/vt_http_api.cpp, producer/pr_http_api.cpp Login endpoints The VoicTune and Producer daemon login endpoints do not have rate limiting (the main admin binary does). These run on separate ports (8350/8354, 8360/8364) and share the same credentials. Low Priority
12 LOW Denial of Service http_api.cpp serve_file() serve_file() reads entire files into memory with std::istreambuf_iterator. Only web assets are in the webroot (small files), so practical exploitation is limited. Accepted Risk
13 LOW Cookie SameSite http_api.cpp Set-Cookie Session cookies use SameSite=Lax (changed from Strict to fix cross-port navigation). While Lax provides CSRF protection for non-GET requests, it still allows top-level navigation GET requests to carry the cookie. Accepted Risk
14 LOW innerHTML Usage js/*.js ~50 instances JavaScript files use innerHTML extensively for DOM updates. Most data comes from API responses (server-controlled), not direct user input. The esc() function is used for user-derived strings. No direct XSS vectors found, but the pattern increases attack surface if API responses are ever poisoned. Accepted Risk
15 INFO SQL Injection Prevention All PHP APIs - All PHP database queries use PDO prepared statements with ? parameter binding. The Mc1Db trait's rows(), row(), run(), scalar() methods all use prepared statements. No SQL injection vectors found in PHP code. N/A
16 INFO SQL Injection Prevention All C++ source - All C++ SQL queries use Mc1Db::escape() or VtDb::escape() (which call mysql_real_escape_string()) for all string values. Integer values use std::to_string() or %d format specifiers. No SQL injection vectors found in C++ code. N/A
17 INFO Command Injection Prevention All PHP APIs - All 60+ exec()/shell_exec() calls in PHP use escapeshellarg() on all variable arguments. Verified across: tracks.php, podcast.php, forensic.php, daw.php, captions.php, producer.php, hls.php, srt.php, rtmp.php, ads.php, ndi.php, health.php. N/A
18 INFO XSS Prevention All PHP pages - All PHP pages use h() (alias for htmlspecialchars(ENT_QUOTES|ENT_HTML5)) for HTML output. Public pages (widget.php, podcast-site.php, request-widget.php, remote-guest.php, podcast_feed.php) all escape user-derived data. The podcast_feed.php uses dedicated xe() for XML escaping. N/A
19 INFO Auth Coverage All endpoints - All API endpoints have mc1_is_authed() gates. The 6 intentionally public endpoints are documented: podcast_feed.php (RSS), request-widget.php (listener requests), widget.php / widget-hls.php (embeddable players), remote-guest.php (recording guest), podcast-site.php / podcast-episode-page.php (public podcast site). The C++ with_auth() wrapper protects all /api/v1/ routes except /api/v1/auth/login. N/A
20 INFO Upload Security app/api/upload.php - File upload handler uses: realpath()-based allowed root validation, audio-only extension whitelist, filename sanitization via regex, move_uploaded_file(), and duplicate name handling. No path traversal or arbitrary file write vectors found. N/A
